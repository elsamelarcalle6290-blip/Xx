# 百家号15篇批量生产流程

这个文件专门用于百家号批量生产任务。

当用户提供一个包含几百条或几千条文章链接、标题、阅读量、评论量、发布时间、平台数据、素材摘要或原文内容的文件时，直接按本流程执行。

## 1. 调用顺序

批量生产百家号文章时，按下面顺序使用本地提示词：

1. 先读取本文件，确定批量筛选与生产流程。
2. 再读取 `创作偏好与素材路径.md`，确定百家号的选题偏好、写作口味、标题要求和禁用表达。
3. 再读取 `百家号排版规范.md`，确定最终成稿的标题、正文、分隔线、加粗和复制粘贴格式。
4. 再参考 `自媒体爆款写作精雕大师（金字塔原理与十八种引流标题法）.md`，只把其中的标题方法、金字塔结构和段落打磨方法作为内部参考。

主提示词里的分步确认流程只在用户明确要求共创、选题脑暴、标题备选或逐段打磨时使用。

如果用户只是给文件并要求写文章，不展示分步过程，不要求用户逐步确认，不输出10个标题、3个大纲、摘要选择或段落确认。

## 2. 默认任务目标

默认从用户提供的大批量素材中筛选出最适合百家号发布的15条，写成15篇百家号成稿。

如果用户指定数量，以用户指定数量为准。

如果文件里的素材不足以支撑15篇成稿，优先保证质量，不为了凑数量选择明显低质、低可信、无法核验或信息量过薄的素材。

## 3. 筛选标准

筛选时优先看这些因素：

1. 数据表现：阅读量、评论量、转发量、收藏量、互动率、热度排序等。
2. 话题价值：是否和普通人的钱袋子、生活成本、市场情绪、产业变化、规则公平、政策影响有关。
3. 事实密度：是否有清楚的人物、机构、时间、地点、数字、处理结果、政策变化或市场动作。
4. 争议空间：是否能引出普通读者愿意评论的问题，但不能靠低俗、造谣、仇恨或标题党制造争议。
5. 可核验程度：是否能通过公开信息、官方渠道、权威媒体、公告、财报、监管文件或原始报道进行核验。
6. 平台适配：是否适合百家号读者阅读，不优先选纯猎奇、纯情绪、无事实支撑、擦边低俗或无法落到现实影响的话题。

## 4. 筛选偏好

百家号优先选择：

1. 财经、券商、A股、银行、利率、分红、监管、基金、楼市、消费、就业等能让普通人产生代入感的话题。
2. 科技、芯片、稀土、供应链、制造业、能源、AI、算力等能讲清产业影响的话题。
3. 国际关系、贸易摩擦、签证、制裁、外交表态、国家安全等有清楚事实线的话题。
4. 教育考试、公共安全、民生成本、出行风险、平台规则等能落到具体生活的问题。

不优先选择：

1. 只有情绪、没有事实的内容。
2. 标题很炸但原文信息很薄的内容。
3. 无法核验来源的爆料、截图、传言、二手搬运。
4. 明显低俗、猎奇、擦边、地域攻击、群体攻击的内容。
5. 需要大量编造背景才能写成文章的内容。

## 5. 联网核验

涉及最新时事、财经市场、上市公司、政策监管、国际关系、公共事件、人物职务、机构表态、数字变化时，必须围绕同一事件联网核验。

联网核验只补足与原文核心直接相关的事实，不把文章写成资料堆砌。

优先使用：

1. 官方公告、监管文件、交易所公告、公司公告、财报。
2. 权威媒体、主流媒体、行业机构公开数据。
3. 与原文同一事件、同一主体、同一时间线直接相关的公开报道。

禁止使用：

1. 未证实截图。
2. 营销号二手转述。
3. 网友评论冒充事实。
4. 其他文章的无关素材硬塞进本篇。
5. 为了增强冲突而编造专家观点、内部消息、对话和细节。

## 6. 写作方式

每篇文章都要像真人作者在讲一件具体事，而不是写成抽象观点稿。

推荐节奏：

1. 开头先抓住普通读者的直觉、担心、误会或情绪。
2. 马上讲清事实：谁做了什么、什么时候发生、涉及哪些数字、规则、机构或结果。
3. 先承认事件里合理的一面，不要一上来就扣帽子。
4. 再自然降温：好事不等于风险消失，表态不等于落地，分红不等于闭眼买，龙头不等于不会跌。
5. 拆清真正变量：利润质量、行业周期、成交量、执行力度、责任边界、违规成本、供应链依赖、审核流程、对等原则等。
6. 最后落到普通人：读者该看什么，别被什么带偏，真正值得关注的变化在哪里。

写作时可以参考用户给过的旧写法：

1. “市场一有监管消息，散户最容易兴奋。”
2. “券商股一有动静，市场就容易激动。”
3. “市场里最容易让人误会的，就是‘龙头不会倒’。”

学习的是节奏和判断方式，不照搬原句。

## 7. 标题要求

每篇只输出1个标题。

标题控制在30-64个中文字符。

标题要说清楚事件核心、冲突点或现实影响，不要只写空泛情绪。

标题不要标注标题类型，不要输出备选标题，不要写“标题一、标题二”。

## 8. 正文字数

正文不设死板字数。

根据原文信息量、事件复杂度和核验资料决定篇幅。

原则是：信息量足的内容写完整，信息量薄的内容不硬凑；能讲透就写长，讲不透就收住。

不能为了凑字数重复观点，不能把同一个意思换说法堆满全文。

## 9. 输出格式

每篇文章默认输出为：

```text
# 标题

**开头关键句**

正文第一段……

正文第二段……
```

每篇之间用分隔线隔开，方便用户复制。

可以使用标题符号和少量加粗，让标题和正文容易区分。

不要输出筛选理由、写作角度、封面建议、重点句、追问、摘要、大纲、数据说明、原文链接说明。

## 10. 禁用表达

正文中禁止出现这些暴露写作过程或模板感太重的表达：

1. 素材称
2. 原文提到
3. 这篇内容提到
4. 这件事看起来是一个新闻点
5. 这类议题之所以容易引起讨论
6. 公众真正关心的是
7. 写作角度
8. 封面建议
9. 重点句
10. 追问
11. 引言
12. 事件回顾
13. 目前处理结果
14. 事例分析
15. 写在最后
16. 那么小编想问
17. 现实账
18. 规则账
19. 值得重新看

不要写成“我在分析素材”，要写成读者可以直接发布的正文。

## 11. 成稿检查

每篇写完后，内部检查一次：

1. 标题是否在30-64个中文字符之间。
2. 是否只有标题和正文，没有多余说明。
3. 是否出现禁用表达。
4. 是否把不确定信息写成确定事实。
5. 是否有“可以买、必涨、抄底、上车”等投资诱导。
6. 是否跨文章混用了别的素材。
7. 是否像真人文章，而不是抽象观点讨论。

确认通过后再交付。
