# 文章排版输出规范

这份文件用于统一文章成稿的排版方式。以后凡是输出自媒体文章、新闻评论、争议文、论说文、爆款改写稿，默认都要按本规范排版。

如果用户明确要求“纯文本”“不要 Markdown”“不要加粗”“不要标题层级”，以用户当次要求为准。

---

## 一、总原则

文章不仅要写得顺，还要看得舒服。

默认使用 Markdown 排版，让读者在手机和电脑上都能快速扫到重点。

排版目标：

1. 段落清楚，不堆成一整块。
2. 重点词有标记，但不过度花哨。
3. 正文结构清楚，但不要露出模板化栏目名。
4. 关键事实、核心矛盾、文末追问要突出。
5. 直接引用要用中文双引号，不能把自己总结的话伪装成原话。

---

## 二、文章默认结构

正式文章默认按以下结构排版。注意：写作结构可以用于组织思路，但正文里不要出现“引言”“结语”“写在最后”“那么小编想问”等模板化栏目名。

```markdown
## 备选标题

1. 标题一
2. 标题二
3. 标题三
4. 标题四
5. 标题五

## 写作结构

1. 开头：先抛出主题或核心矛盾。
2. 展开：讲清事实、背景和主要争议。
3. 转折：写出真正值得讨论的地方。
4. 收束：给出有余味的判断或追问。

---

## 正文

正文段落……

正文段落……

正文段落……

正文段落……
```

如果用户只要正文，可以省略“备选标题”和“写作结构”，直接输出自然段正文。除非用户明确要求小标题，否则正文内部不强行加小标题。

---

## 三、重点词标记

默认使用以下标记方式：

1. **加粗**：用于关键人物、关键时间、关键数据、核心结论、争议焦点。
2. **【重点句】**：用于一篇文章中最需要读者记住的核心判断、关键反问或结尾槽点。
3. “中文双引号”：用于素材中明确存在的原话、标题、文件名、政策名、争议说法。
4. `代码样式`：只用于文件名、平台名、专有命令或技术词，不用于普通文章强调。

使用强度：

1. 每个自然段最多加粗 1-2 处。
2. 每篇文章重点句标记建议 2-5 处，不要每段都标。
3. 不要整段加粗。
4. 不要同时对同一句话加粗、重点标签、引号三连叠加，除非用户明确要求。

---

## 四、双引号规则

1. 直接引用素材原话时，用中文双引号：“……”
2. 引用网友、专家、官方、当事方说法时，必须是素材或联网核验中明确出现的内容。
3. 自己概括的观点不能写成原话，只能写：
   - 有一种观点认为，……
   - 也有人担心，……
   - 公众真正追问的是，……
4. 标题、政策名、文件名、平台口号可用双引号标出。

错误示例：

> 有知情人表示：“这事早就有人知道。”

如果素材没有这句话，就不能这样写。

正确示例：

> 从目前公开信息看，真正的疑问是：“问题到底卡在哪个环节？”

---

## 五、重点句标记规则

不要使用 HTML 下划线标签，也不要在文章中输出相关 HTML 标签符号。

默认用下面两种方式突出关键句：

```markdown
**【重点句】这里是需要读者停一下的核心判断。**

**【追问】这里是文末最需要引发讨论的问题。**
```

适合使用重点句标记的位置：

1. 开头第一屏的核心判断。
2. 每个大段落里最关键的一句结论。
3. 文末最需要引发讨论的核心争议问题。

不要给普通事实句乱加【重点句】。重点句标记是“提醒读者停一下”，不是装饰符号。

---

## 六、小标题规则

小标题要短、具体、有信息量。

正文内部默认不使用模板化小标题。确实需要小标题时，要写成具体信息型标题，不要使用“引言”“结语”“写在最后”“那么小编想问”等栏目名。

推荐格式：

```markdown
### 【争议焦点：为什么这件事让人不舒服？】

### 【问题卡点：规则为什么没有及时落地？】

### 【责任边界：不能只靠一句道歉收场】
```

小标题不要写成空话：

不推荐：

```markdown
### 深度分析
### 引发思考
### 多方关注
```

推荐：

```markdown
### 【争议焦点：责任不能只停在一句道歉上】
```

---

## 七、段落和节奏

1. 每段控制在 80-180 个汉字左右。
2. 信息复杂时，多拆短段。
3. 连续 3 段以上都是长段时，要主动拆分。
4. 时间线、处理结果、数据对比，优先用列表。
5. 反问句可以单独成段，用来加强节奏。

时间线示例：

```markdown
- **5月10日**：事件首次被公开讨论。
- **5月12日**：相关部门发布情况说明。
- **5月14日**：涉事方回应争议。
```

数据对比示例：

```markdown
- **原始说法**：……
- **最新公开信息**：……
- **需要修正的地方**：……
```

---

## 八、开头排版

开头要短、硬、好扫。不要把开头标成“引言”，直接进入正文。

推荐写法：

```markdown
这件事最刺眼的地方，不是某个人说错了一句话，而是一个更现实的问题：

**【重点句】当规则只停在纸面上，最后买单的往往是最普通的人。**

事情看起来不复杂，可越往下看，越让人觉得不对劲。
```

---

## 九、收束排版

文末默认自然收束，不使用“结语”“写在最后”“那么小编想问”等栏目名。

推荐分两步完成：

1. 先收住观点，回到全文最核心的问题。
2. 再用一句有讨论价值的追问或判断留下余味。

示例：

```markdown
一件事能不能过去，不看热搜什么时候降温，而看问题有没有真正解决。

道歉可以很快，通报也可以很快，但公众要的不是一句漂亮话，而是一个能落地的答案。

**【追问】如果每次都要等到舆论闹大才有人重视，那到底是规则在保护人，还是热搜在替规则上班？**
```

---

## 十、不要这样排版

1. 不要满篇加粗，重点会失效。
2. 不要每句话都加【重点句】或【追问】。
3. 不要乱用英文引号 `"..."`，中文文章默认用 “……”。
4. 不要把素材没有的内容包装成引用。
5. 不要用太多分割线，一篇文章 1-2 条 `---` 就够。
6. 不要让标题、大纲、正文混在一起，必须分区。
7. 正文不要出现“引言”“结语”“写在最后”“那么小编想问”等模板化栏目名。

---

## 十一、最终检查

文章输出前检查：

1. 是否有清晰标题区、正文区。
2. 正文是否自然形成开头、展开、转折、收束，而不是靠模板栏目名硬撑结构。
3. 是否重点词做了加粗。
4. 是否至少有 1-3 个真正关键的【重点句】或【追问】。
5. 是否直接引用都用了中文双引号。
6. 是否没有虚构“知情人”“网友”“专家”等来源。
7. 是否没有一整屏都是密密麻麻的长段落。
