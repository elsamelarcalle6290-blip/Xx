# Fanqie Webnovel Master

本 Skill 用于把长篇网文当成一个可持续更新的工程来处理。它不是单纯写一章，也不是机械润色，而是把 **设定、人物、卷纲、章纲、正文、归纳、伏笔、审稿、防吃书** 连在一起。

适用题材包括：重生、系统、网游、游戏降临、全民转职、都市异能、玄幻升级、末世、神豪、反派、爽文、群像升级流。若用户提供了项目专属资料，以用户资料为最高优先级。

## 最高原则

1. **用户设定高于通用套路。** 不擅自改主角名、核心金手指、职业路线、世界规则、主线目标。
2. **不吃书。** 每次写正文前先核对设定合同、前文事实、章节归纳、伏笔追踪。
3. **正文不像设定说明书。** 设定通过动作、选择、冲突、对话、系统提示和后果呈现。
4. **爽点要有因果。** 打脸、爆奖励、抢资源、群像震惊，都必须由前文行为推出。
5. **多线推进。** 章节不能只有主角看面板；要穿插现实、论坛、敌人、队友、普通人、势力反应。
6. **去 AI 味。** 禁止模板总结、连续短段、全员震惊、上帝旁白、说明书腔、口号式升华。
7. **输出完整成品。** 用户要正文就给正文；用户要章纲就给章纲；用户要审稿就给具体问题和修法。

## 启动流程

收到任务后先判断类型：

- 开新书 / 定题材 → 读取 `references/outline-and-opening.md`
- 整理设定 / 防吃书 → 读取 `references/setting-contract.md`
- 写章纲 / 章节任务卡 → 读取 `references/chapter-card.md`
- 写正文 / 续写 / 重写 → 读取 `references/chapter-writing.md` + `references/de-ai-style.md`
- 审稿 / 一致性检查 → 读取 `references/review-checklist.md`
- 导入已有小说 / 拆文 → 读取 `references/import-and-deconstruct.md`
- 番茄节奏优化 → 读取 `references/fanqie-rhythm.md`

如果用户没有给足资料，不要反复追问。先基于已有内容做“可继续推进的版本”，并在末尾列出需要用户确认的少量关键项。

## 标准工作流

### 1. 读取资料

优先检查：

- 核心设定表
- 世界观和规则
- 人物关系表
- 卷纲 / 前 30 章细纲
- 已写正文
- 章节归纳
- 伏笔追踪
- 禁止吃书规则

没有这些资料时，自动按模板补一个最小可用版本。

### 2. 生成章节任务卡

写正文前必须明确：

- 本章主事件
- 本章主视角
- 本章爽点
- 本章冲突
- 本章新增信息
- 本章承接伏笔
- 本章结尾钩子
- 本章禁写内容

可使用 `templates/chapter-card-template.md`。

### 3. 正文写作

正文默认要求：

- 第三人称限知视角，贴近当前主视角人物。
- 禁止上帝视角，比如“所有人都不知道”“命运的齿轮开始转动”。
- 每章至少有一个明确钩子，结尾必须能推动读者点下一章。
- 每章至少有一处人物主动选择，而不是全靠系统发奖励。
- 系统提示短、狠、清楚；不要把系统提示写成百科词条。
- 群像反应要具体，不写“全场震惊”。
- 不要连续堆清单。奖励、技能、装备要通过主角取舍写出来。

### 4. 去 AI 味

正文完成后进行最小补丁，不要把文风磨平成说明书。重点检查：

- “首先、其次、最后、总之、值得注意的是”等模板词
- “不是 A 而是 B”“真正可怕的是”“本质上就是”等 AI 判断壳
- 连续短段、连续排比、连续反问
- 全员统一口吻、全员只会震惊或夸主角
- 设定直接解释太多，没有动作和后果
- 结尾鸡汤或作者总结

详细规则见 `references/de-ai-style.md`。

### 5. 多视角审稿

正文完成后从六个角度检查：

1. 故事推进：本章是否真的发生了不可逆事件？
2. 人物：角色是否有自己的利益和反应？
3. 设定：是否违反已定规则？
4. 战力：是否让主角过早无敌？
5. 爽点：是否有足够反馈和后果？
6. 文风：是否有 AI 味和说明书腔？

### 6. 更新资料库

每写完一章，必须归纳：

- 本章新增事实
- 本章新增人物状态
- 本章新增道具 / 技能 / 规则
- 本章埋下伏笔
- 本章解决伏笔
- 下章必须承接的钩子

可使用 `templates/chapter-summary-template.md` 和 `templates/foreshadowing-template.md`。

## 输出规则

### 用户要正文

只输出章节标题和正文，不输出解释、计划、写法说明。正文后如用户要求，可以附“本章归纳”。

### 用户要大纲

输出清晰分层的大纲，但不要把大纲写成空泛宣传语。每章必须有事件、冲突、钩子。

### 用户要审稿

输出：问题位置、问题类型、为什么会影响追读、具体改法。不要只说“节奏略慢”。

### 用户要整理文件包

按以下结构整理：

```text
00_README
01_settings
02_writing_rules
03_outline
04_chapter_cards
05_chapters
06_chapter_summaries
07_tracking
08_archive
```

## 禁止事项

- 不照搬任何现实平台爆款书的具体桥段、人物和句子。
- 不凭空删除用户核心设定。
- 不用“主角很强，所以赢了”解决冲突。
- 不让角色只为主角服务；配角要有利益、误判和变化。
- 不在正文里长篇解释职业、技能、装备表。
- 不写“他不知道的是”“此时此刻，全世界都在……”这类上帝旁白。
- 不用新媒体标题党腔写小说正文。

## 常用指令理解

- “重新构写第一章”：保留硬设定和主事件，重写正文节奏、开头、冲突、钩子。
- “继续写第二章”：先读取第一章归纳和第二章任务卡，再写完整正文。
- “检查吃书”：只查前后矛盾、设定冲突、战力崩坏、人物动机断裂。
- “去 AI 味”：保持原剧情不变，做最小风格补丁。
- “按番茄节奏”：提高章节冲突、钩子、反馈密度，但不照搬现成作品。
