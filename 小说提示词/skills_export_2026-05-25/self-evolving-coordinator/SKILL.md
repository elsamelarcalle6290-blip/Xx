# 自我进化与协同调度技能

## 用途
本技能是创作系统的“学习中枢”与“调度中心”。负责从历史创作、读者反馈、人工审核、执行日志与协同结果中持续学习，沉淀经验教训，自动优化写作与执行策略，并基于任务需求，识别并调度最适合的执行技能进行协同工作，形成“执行—反馈—学习—优化—再执行”的闭环。

## 核心原则
- 交互即训练：每次任务结束，必须提取经验并更新内部知识库
- 错误不二犯：识别错误模式，写入避错库，下次自动拦截
- 偏好可习得：从反馈中学习，动态调整策略模型权重
- 知识可沉淀：新设定、新写法、新规则自动归档入库
- 进化可追溯：每次调整记录版本，支持回溯与回滚
- 调度最优化：评估任务复杂度，匹配最佳技能组合执行
- 结果可验证：策略变更必须通过观察窗口验证后才能固化
- 规则可继承：已验证的高质量策略可跨项目复用
- 风险可隔离：高不确定性调整先做局部验证，避免全局波动
- 协同可审计：所有协同过程保留关键节点记录，便于复盘

## 工作流程

### 第一阶段：后台学习与进化

此流程为后台行为，不应中断主任务，除非需要即时应用拦截规则。

#### Step 1: 事件触发
识别触发学习的事件来源，包括：
- 完成一章创作
- 完成一次协同任务
- 收到审核报告或编辑反馈
- 读者反馈数据更新（本章说、追读率、收藏/催更）
- 月度复盘时间到达
- 完成一本书、一个系列或大型项目
- 发现明显质量波动、风格漂移或协同失败
- 平台规则、受众偏好或竞品趋势发生变化

#### Step 2: 多源日志分析
根据事件类型，从相应来源扫描并提取关键信号：

**内部来源分析：**
- 已写章节：识别成功句式、失败表达、节奏模板
- 审核报告：提取高频错误、质量波动规律
- 优化记录：标记AI痕迹高频位置、冗余模式
- 伏笔回收：总结成功或失败的埋设策略
- 协同过程日志：识别任务拆分是否合理、是否存在等待阻塞
- 版本变化记录：判断调整是否带来稳定提升

**外部来源分析：**
- 读者本章说：捕捉情绪反应点、疑惑点、期待方向
- 追读率波动：推测弃书点，验证爽点有效性
- 收藏/投票/打赏波动：验证内容吸引力与角色认可度
- 同品类热书：拆解新套路、新爽点设计、命名趋势
- 编辑反馈：记录平台偏好变化、合规新要求
- 竞品评论区：提取常见期待、吐槽与可借鉴设计

#### Step 3: 模式识别与知识提取
将识别到的模式填入对应的学习模块：

**模块一：错误模式捕获与避错**
```md
【错误登记】
错误类型：（重复句式/逻辑矛盾/命名违规/节奏崩塌/协同冲突/信息过载/角色失真/其他）
出现环节：第X章第X段/第X任务第X步骤
错误表现：
根因分析：
修正方案：
拦截规则：（写进自检清单的检测条件）
影响等级：（轻微/中等/严重/系统级）
复发概率：（低/中/高）
```
- 同类错误连续出现3次，自动升级为系统级高优先级拦截规则
- 严重错误优先进入“即时拦截”队列，必要时暂停输出并修复
- 所有错误每月回顾一次，分析同源性并合并规则
- 对于低风险但高频错误，优先通过模板修复而非单点修复

**模块二：成功模式识别与强化**
```md
【成功登记】
模式类型：（开篇钩子/章末断章/打脸爽点/情感渲染/战斗描写/协同方案/悬念布局/反转设计/其他）
出现位置：第X章/第X任务节点
成功表现：（追读提升/本章说激增/读者正面反馈/协同效率提升/完成度显著提高）
可复用要素：
泛化模板：（提取为可跨书、跨任务使用的公式）
使用条件：（明确适用场景）
可替换变量：（人物、场景、冲突、目标、节奏）
```
- 已验证的成功模式进入“常用武器库”，同类场景优先调用
- 成功模式若与旧模板重叠，优先保留更高转化率版本
- 每月整理TOP10最佳片段，周期性回顾以决定保留或降级
- 对高响应模式进行拆解，提炼“核心刺激点”与“实现路径”

**模块三：交互偏好与风格建模**
```md
【偏好维度】
文风密度：轻松←——→厚重（当前权重：0.7）
节奏速度：舒缓←——→紧凑（当前权重：0.8）
爽点类型：智斗/碾压/收获/情感/揭秘/逆袭/反差（分布：智斗0.4 碾压0.3 ...）
建议风格：直接/详细/克制/爆发（当前权重...）
对话比例：当前偏好35%
描写密度：当前偏好中等
断章风格：悬念型0.5 / 预告型0.3 / 揭露型0.2
冲突强度：低/中/高（当前：中）
信息释放速度：慢/中/快（当前：中快）
```
- 正面反馈 → 对应偏好权重 +0.02
- 负面反馈 → 对应偏好权重 -0.03
- 单次变化超0.15，需用户或人工确认
- 若偏好波动持续3次，降低权重更新幅度，防止模型震荡
- 不同任务场景可采用不同偏好子模型，避免“一套权重走天下”

**模块四：知识库进化**
```md
【新增入库】
类型：（世界观模板/职业设定/能力设计/对话风格/战斗模板/协同方案/命名规则/节奏结构/其他）
内容摘要：
来源：（原创/热书提取/历史素材/协同任务/用户反馈）
使用场景标签：
质量评级：S/A/B/C
复用范围：（单项目/同题材/跨题材/全局）
依赖关系：（与哪些模板联动）
```
- 每本书完结时，全书精华提取入库
- 库容超1000条后，每月清理低使用率（<3次/月）且非高评级的条目
- 高评级条目如长期未调用，也需保留但降权，而非直接删除
- 同一知识点若存在多个版本，保留“最新高效版”与“稳定版”双轨结构

**模块五：策略分析与优化建议**
```md
【策略评估】
策略名称：
适用场景：
当前效果：
问题诊断：
优化建议：
验证方式：
观察周期：
是否进入正式版本：（是/否）
```
- 所有策略优化必须明确“目标—指标—验证周期”
- 优化建议优先支持局部试验，避免一次性大改
- 若策略调整未达阈值，则自动回滚并记录失败原因
- 对与平台、题材、用户偏好强相关的策略，增加场景标签限制

#### Step 4: 更新知识库与规则
- 将新提取的知识沉淀入库
- 激活新的拦截规则或强化规则
- 入库前检查是否与旧条目高度相似，避免知识库膨胀
- 对冲突条目进行优先级排序，保留更通用或更高成功率者
- 标记“待验证”条目，避免未经验证即被广泛调用

#### Step 5: 策略版本记录与进化
涉及策略变动时，生成新的策略版本快照：
```md
【策略版本记录】
版本号：V2.3
更新时间：
触发原因：（追读率连续下降3章 / 协同效率瓶颈 / 错误重复出现 / 平台规则变更）
调整项：
· 开篇节奏：从500字建立冲突 → 200字建立冲突
· 章末钩子：从预告型为主 → 悬念型为主
· 调度策略：从串行执行 → 并行执行非依赖性子任务
· 风格控制：从高密度叙述 → 关键节点高密度，过程低密度
调整后效果：（观察验证10章或10次任务后评估）
回滚条件：
```
- 新策略必须经过小批量验证才可正式上线
- 保留最近5个策略版本，效果不佳时可随时回滚
- 版本变更需记录“变更前/变更后/验证结果/结论”
- 若多次版本迭代仍无改善，自动降级为保守策略

#### Step 6: 按触发条件执行进化动作
| 触发条件 | 进化动作 |
|---------|---------|
| 连续3章追读率下降 | 自动分析下降点，提出策略调整方案 |
| 同类错误出现3次 | 自动升级避错规则，写入自检清单 |
| 某类爽点本章说激增 | 标记高响应模式，增加同类内容投放 |
| 读者集中反馈某问题 | 提取共性，生成修复任务 |
| 完成一本书或大型项目 | 全书/全项目复盘，提取所有可复用资产 |
| 平台规则变更 | 更新合规库，标记受影响章节 |
| 同品类出现新爆款 | 拆解新套路，标记可借鉴要素 |
| 协同效率明显下降 | 重新拆分任务，优化技能调用顺序 |
| 策略验证失败 | 回滚到上一稳定版本，并标注失败原因 |

### 第二阶段：协同调度执行

当任务复杂度超出单一技能处理能力时，本模块作为“调度中心”执行协同。

#### Step 1: 需求解析
接收用户的复合指令，判断是单一任务还是复合任务。
- 单一任务：直接执行，减少中间拆分
- 复合任务：识别依赖关系、优先级与可并行部分
- 模糊任务：先做最小必要澄清，再进入拆解

#### Step 2: 方案制定与确认
1. 将复杂需求拆解为可独立执行的步骤链
2. 扫描技能库，检索当前可用的所有专业技能
3. 匹配合适的执行单元
4. 生成协同计划，明确执行顺序和中间产物传递
5. 以精简方式向用户展示关键步骤并获取确认

协同计划使用标准化语言：
```md
【协同指令】
任务目标：[一句话描述最终要交付什么]
执行计划：
Step 1：[技能A] 负责 [子任务]，产出 [文件名A]
Step 2：[技能B] 基于 [文件名A] 负责 [子任务]，产出 [文件名B]
Step 3：[技能C] 基于 [文件名B] 负责 [子任务]，产出 [文件名C]
...
最终输出：[将所有产出整合到最终文件]
约束条件：[必须遵守的规则和风格要求]
优先级规则：[哪些先做、哪些可并行]
风险点：[可能失败的环节与备选方案]
```

#### Step 3: 调度执行
- 按计划依次调用各技能，并传递必要数据
- 监控各模块按计划执行，处理中间环节的异常
- 对可并行任务优先并行执行，降低总耗时
- 对依赖强的任务保持串行，避免产物冲突
- 若指定技能缺失或执行失败，启动保底方案或请求人工干预，确保不中断任务
- 若出现输入不完整、冲突或超出能力边界，及时返回澄清请求或降级方案

#### Step 4: 整合交付
- 收回所有子产物
- 进行最终校对与整合
- 统一格式、术语和风格
- 消除重复、冲突和逻辑断点
- 将最终单一结果交付用户

#### Step 5: 触发学习
协同任务完成后，自动跳转至第一阶段，对本次协同效率和产出质量进行评估和学习。
- 记录各技能贡献度
- 记录拆解是否合理
- 记录等待时间、返工次数与失败点
- 更新“最佳协同路径”模板
- 更新“低效调用组合”黑名单

## 自检清单
完成每次任务后，检查以下事项：
- 刚完成章节或任务是否已提取经验
- 新错误是否已登记到避错库
- 新成功模式是否已入库
- 偏好权重是否需要更新
- 知识库是否有新增条目
- 策略是否需要调整（观察数据是否触发阈值）
- 月度复盘是否已执行
- 避错规则是否有新增或升级
- 协同过程是否有阻塞、返工或冗余
- 是否存在可并行未并行的任务节点
- 当前版本是否需要验证、保留或回滚
- 高风险结论是否已标记为“待验证”
- 输出是否符合当前用户目标与约束

## 重要规则
- 学习是后台行为：不应中断当前主任务流程，除非需要即时应用拦截规则
- 协同计划必须精简：只向用户展示最顶层的关键步骤，无需罗列所有技术细节
- 知识条目去重：入库前必须检查是否与旧条目高度相似，避免知识库膨胀
- 调度失败处理：如果指定技能缺失或执行失败，必须启动保底方案或请求人工干预，不得中断整个任务
- 策略验证机制：新策略必须经过小批量验证才可正式上线，保留最近5个版本支持回滚
- 风格切换要可控：切换文风、节奏或爽点类型时，必须保留稳定输出底线
- 高风险变更先局部试验：涉及大范围改写、结构重组或调度方式更改时，优先做局部验证
- 版本记录必须完整：每次进化都要保留触发原因、修改内容、验证结果与结论
- 失败不是终点：失败结果必须转化为明确的修正规则或禁用条件
- 任何冲突优先保交付：若学习与交付冲突，以当前任务可完成度为最高优先级
